# passmgmt

加密资源库（桌面版网页应用）。把文本、照片、文件作为条目集中加密保存成一个 `.vault` 文件；用密码打开、修改，再重新加密导出为新文件。

纯前端，无后端，数据只在内存和你导出的文件里。

必须通过 `http://` 或 `https://` 访问（WebCrypto 只在安全上下文可用），不能直接双击打开 `dist/index.html`。

## 继续开发

新会话或新协作者先读 `CLAUDE.md`（设计原则、约束、当前状态、下一步），详细进度见 `PROGRESS.md`。仓库是自包含的，不需要外部会话记忆。

## 运行

```bash
npm install
npm run dev           # 开发：http://localhost:5173
npm test              # 单元测试
npm run build         # 普通静态构建，产物在 dist/
npm run build:single  # 单文件构建，产物是 dist-single/passmgmt.html
npm run build:pwa     # PWA 构建，产物是 dist-pwa/
```

## 单文件版本

`npm run build:single` 会把 JS、CSS、hash-wasm 的 WASM、Argon2 Worker 全部内联成一个 HTML：

```
dist-single/passmgmt.html
```

约 370 KB，双击即可在桌面浏览器打开，不需要服务器。数据仍然是单独的 `.vault` 文件，通过选择文件导入、下载导出。

已在 Edge 的 `file://` 下验证：创建库、内联 Argon2 Worker、TOTP、密码生成、导出、锁定后重新导入均正常，控制台 0 错误。

iOS 上本地 HTML 的行为取决于系统版本和打开方式，不能保证 WebCrypto、Worker、文件保存都可用。如果要在 iPhone 上稳定使用，建议用 PWA（HTTPS 静态托管 + 添加到主屏）；单文件版可以先生成出来在手机上试。

## PWA 版本

```bash
npm run build:pwa
```

产物是 `dist-pwa/` 静态目录，把它部署到任意 HTTPS 静态托管（Cloudflare Pages、Netlify、GitHub Pages、自己的服务器等）的站点根目录，然后在 iPhone Safari 里打开 → 分享 → **添加到主屏幕**。

- 首次加载后 Service Worker 会缓存全部应用资源，断网也能打开。
- 数据仍然只在设备上；托管服务器只下发程序文件，不接触 `.vault`。
- `start_url` / `scope` 是 `/`，需要部署在站点根目录；如果部署在子路径，需要同时调整 Vite `base` 和 manifest 路径。
- 单文件版用于桌面本地双击；PWA 版用于 iOS 主屏和离线。
- iOS Safari 没有 File System Access API，保存仍然是一次新的下载。

### 部署到 GitHub Pages

仓库里已经包含 `.github/workflows/deploy-pages.yml`，流程是 `npm ci` → `npx tsc --noEmit` → `npm test` → `npm run build:pwa` → 发布 `dist-pwa/`。

1. 在 GitHub 创建仓库，把本地 `main` 推上去。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。

   如果工作流报 `Get Pages site failed`，说明 Pages 还没有启用：先完成这一步，然后重跑工作流。工作流里的 `configure-pages` 也带了 `enablement: true`，公开仓库下会尝试自动启用。首次启用后第一次运行仍可能 404，这是 Pages 站点创建/传播的延迟，重跑一次即可。

   如果 Settings 里没有 Pages 或提示不可用，通常是因为仓库是私有且套餐不支持。免费账号请把仓库设为 **public**（仓库只含代码，`*.vault` 不会入库），或升级套餐；也可以改用 Cloudflare Pages（免费版支持私有仓库）。

3. 之后每次 push 到 `main`，或手动运行 **Deploy PWA to GitHub Pages** 工作流，都会构建并发布。
4. 项目站点地址：`https://<user>.github.io/<repo>/`；如果仓库名是 `<user>.github.io`，地址是 `https://<user>.github.io/`。
5. iPhone Safari 打开该地址 → 分享 → **添加到主屏幕**。

PWA 构建使用相对路径，项目站点和用户站点都适用，不需要改 `base`。

注意：私有仓库发布 GitHub Pages 需要 GitHub 付费计划；否则把仓库设为 public。仓库只包含程序代码，`.vault` 数据永远不会上传。

## 使用

1. **新建**：设置密码，从空库开始。
2. **添加条目**：选择空白条目、内置模板或自定义模板。模板只拷贝字段结构，不预填任何值；条目创建后与模板互不影响。
3. **字段**：字段名 + 类型 + 值。类型有文本、密码、TOTP、文件；文件字段始终允许为空，是否存文件由用户决定。
4. **文件夹**：新建、重命名、删除文件夹，通过条目编辑区的文件夹选择器移动条目。删除文件夹只会把条目移到「未分组」。
5. **模板**：内置模板覆盖网站账号、手机 App、邮箱、游戏、储蓄卡、信用卡、支付宝、微信支付、会员卡、身份证、护照、驾驶证、宽带、收货地址、社保、服务器等场景；账号模板里的「登录平台」只是普通文本字段，由用户自己填写。
6. **搜索**：匹配名称、描述、字段名、文本值、附件文件名。
7. **验证码视图**：左栏顶部切到「验证码」，只列出含 TOTP 字段的条目。每张卡片显示实时验证码、倒计时和复制按钮，并用用户名区分同名账号；点击条目名回到条目视图并打开该条目。
8. **去重**：顶栏「去重」扫描完全相同的条目。名称、描述、字段顺序、字段名、类型、值、附件内容全部相同才算重复；文件夹不参与比较。按组列出后，自己勾选要删除的条目，或点「勾选每组其余条目（保留第一条）」。删除只是修改内存中的库，仍需导出才会写进文件。
9. **导出**：把当前内容重新加密，下载为新的 `.vault` 文件。
10. **导入**：选择 `.vault`，输入密码解密。

用户模板保存在加密库内，随导出文件一起走。未导出就关闭页面，修改会丢失；界面会显示"未导出"状态。

## 验证码视图

左栏顶部有「条目 / 验证码」切换。验证码视图只显示至少有一个 `totp` 类型字段的条目：

- 每张卡片显示条目名、用户名和实时验证码（含倒计时、复制）。
- 用户名按字段名优先匹配，依次查找「用户名、账号、邮箱地址、手机号、登录名、username、account、email」中第一个有值的文本字段。规则固定，不做其他推断；没有匹配字段或值为空时，卡片只显示条目名。
- 一个条目有多个 TOTP 字段时全部列出，并标出各自的字段名。
- 密钥为空或无法解析时，卡片里会直接显示对应的错误状态，不显示假验证码。

## 字段类型

| 类型 | 展示方式 |
|---|---|
| 文本 | 普通多行文本 |
| 密码 | 默认掩码，眼睛图标临时显示；旁边的「生成」打开密码生成器 |
| TOTP | 填入 Base32 密钥或 `otpauth://` URI，右侧实时显示 6/8 位验证码、倒计时和复制按钮 |
| 文件 | 图片显示缩略图，点击直接查看；其他文件下载 |

- **密码生成器**：长度 6–64、大小写 / 数字 / 符号、排除易混淆字符，以及强密码 / 兼容模式 / 纯数字 PIN 预设。点「生成」先打开配置界面，确认后填入字段。密码只填进字段，不自动复制。
- **TOTP**：支持 SHA1 / SHA256 / SHA512、6 位或 8 位、30 秒或 60 秒周期。验证码由密钥实时计算，不会存进库；密钥为空或非法时会明确提示。
- **类型来源**：内置模板和 KeePass CSV 导入会自动设置字段类型；手动添加字段时选择类型，也可以在字段行的类型选择器里随时修改。



## 从 KeePass 导入

工作区顶栏的「导入 CSV」支持两种实际格式：

- **KeePassXC CSV**：`Group, Title, Username, Password, URL, Notes, TOTP, Icon, Last Modified, Created`
- **KeePass 1.x / 2.x CSV**：`Account, Login Name, Password, Web Site, Comments`

映射规则：`Group` 原样作为文件夹名；`Title/Account` → 条目标题；`Notes/Comments` → 描述；`Password` → 密码类型字段；`TOTP` → TOTP 类型字段；用户名、网址 → 对应字段；其它非空列也作为文本字段导入。`Icon`、时间戳等元数据列忽略。空单元格不创建字段。不查重，同一个文件导入两次会产生重复条目。

CSV 是明文，导入后请删除原文件。导入会合并到当前库，并切换到「全部条目」。

## 加密

- 密码 → Argon2id（64 MiB / 3 次 / 1 并行）→ KEK
- KEK 解封随机生成的 DEK（AES-256-GCM 包装）
- DEK 分块加密整个数据体（每块 1 MiB，独立随机 IV）
- 文件头作为 AAD，分块 AAD 绑定块序号和结束标记；篡改、重排、截断都会导致解密失败
- 密码错误或文件损坏：直接失败，不猜测、不修复

**密码丢失 = 数据永久丢失，没有恢复机制。**
